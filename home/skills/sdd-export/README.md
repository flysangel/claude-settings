# sdd-export

在舊專案執行，把這一代的原則、各功能的需求與相依、經驗教訓與世代資訊整理成一份「養分」，
留在舊專案的 `.sdd-export/`，供新專案以 `/sdd-rebuild` 重生時使用。

## 用法

| 指令 | 作用 |
|---|---|
| `/sdd-export` | 匯出整個專案；專案過大時會先列出區塊請你選範圍 |
| `/sdd-export <範圍路徑...>` | 只匯出這些路徑（例如 monorepo 的某個子目錄）；constitution 與 `specs/*/spec.md` 一律會讀 |

- 不需要 Spec Kit：沒有 `.specify/`、不是 git repository、任何語言的專案都可以；不會要求你先執行 `/sdd-init`。
- 只能由維護者輸入 `/sdd-export` 啟動（`disable-model-invocation: true`），Claude 不會主動使用。

## 前置需求

- `uv`：腳本 `scripts/sdd_export.py` 一律以 `uv run` 執行，只用 Python 標準函式庫，不會在專案內建立 `.venv` 或 `uv.lock`。
- `git` 非必要：有的話用來尊重 `.gitignore`、以 commit 作為經驗教訓的依據；沒有時改為走訪目錄樹。

## 流程

1. **讀取（只讀）**：先以腳本的 `check` 檢查專案現況與 `.sdd-export/` 是否可用，再以 `files` 取得可讀的檔案清單
   （排除相依套件、建置產物、被 git 忽略的檔案、二進位檔、鎖定檔與機密檔案）。Claude 只讀這份清單中的檔案，
   不執行建置、測試、安裝或專案自己的腳本，也不在專案內建立任何檔案（包括暫存檔）。
2. **草稿**：有 spec 的功能以 spec 為準，沒有的從文件、設定、測試與程式結構導出「程式碼目前實際的行為」，
   每項附依據檔案，無法確定的標為待確認（`pending`）。疑似 bug、矛盾與改進建議另列為疑點，不混入需求；
   經驗教訓分為重要決定、踩過的坑、被推翻的做法，各附依據，找不到時會問你要不要口頭補充，不會編造。
3. **逐項決定**：依世代資訊、原則、功能、疑點、教訓的順序逐段呈現，每段由你接受、修改或刪除；疑點一題一項。
4. **確認**：腳本驗證草稿（格式、依據是否存在、世代規則、機密樣式），Claude 呈現整體摘要與（再次匯出時）差異，請你確認。
5. **寫入**：確認後才寫入，而且只寫 `.sdd-export/`。

確認之前不寫入任何檔案；中途結束不會留下任何東西，也沒有進度檔，再執行會重新開始。
寫入失敗（例如專案唯讀）時，Claude 會把確認後的草稿完整呈現在對話中。

## 產出

`.sdd-export/` 只屬於 sdd-export，裡面只有三個檔案：

| 檔案 | 內容 |
|---|---|
| `nutrients.json` | 養分本體，唯一的資料來源；`/sdd-rebuild` 讀取它。要手動修改養分時改這個檔案 |
| `README.md` | 由 `nutrients.json` 產生的可讀版本，第一行標明「請勿編輯」；每次寫入都會重新產生 |
| `.gitattributes` | 讓這些檔案在 Windows 與 Linux checkout 時都維持 LF；你改過的話不會被改寫 |

養分的文字內容一律是繁體中文（MUST、SHOULD 等規範詞保留英文），欄位名稱是英文。
`.sdd-export/` 可以提交到 repo（是否提交由你決定，本 skill 不會 commit）；換一台機器時取得舊專案的 repo 即可。
完成後的下一步：在**新專案**執行 `/sdd-rebuild`，並指定這個舊專案的路徑。

## 世代

- 專案沒有 `.sdd-rebuild/lineage.json`（由 `/sdd-rebuild` 在新專案留下的世代紀錄）時，視為第一代。
- 有世代紀錄時沿用它的世代：繼承的項目保留原本的 `id` 與來源世代（`origin`），被修改過的記下修改的世代，
  這一代新增的標為這一代；前代的經驗教訓逐項詢問是否仍然適用；前代捨棄的項目原樣保留。
- 前代的項目不能無聲消失：必須保留、合併到其他項目或明確捨棄，否則腳本會拒絕寫入。這讓第一代的需求在第三代仍可追溯。
- 世代紀錄無法讀取或不符合格式時停止，不會把專案當成第一代（那會切斷世代鏈）。

## 再次匯出

- 已有養分時，再次執行 `/sdd-export` 更新同一份 `nutrients.json`，不產生第二份；以既有養分為起點，依據沒有改變的項目不改寫。
- 確認前呈現新舊養分的差異（新增、移除、修改的新舊值）；沒有差異時會明說。
- 你手動修改過 `nutrients.json` 時，Claude 會先告訴你，要改動那些內容前逐項詢問；手動修改過 `README.md` 時，
  寫入前會提醒它將被重新產生。
- 確認之後、寫入之前若養分又被修改（例如你在另一個視窗編輯），寫入會被拒絕，Claude 重新比對差異後再請你確認。

## 大型專案

可讀檔案超過 1500 個、總大小超過 10 MiB，或有兩個以上的區塊帶有套件描述檔（monorepo）時，
Claude 先列出各區塊的檔案數、大小與描述檔，請你選擇範圍，選定前不讀取任何檔案。
可以分批匯出：每一次確認並寫入的養分都是完整的，之後再執行 `/sdd-export` 選其他範圍，前一次的項目原樣保留，
養分記錄目前涵蓋的範圍（`partial` 或 `full`）。

## 機密

- 不開啟的檔案：`.env` 與 `.env.*`（含 `.env.example`）、`*.pem`、`*.key`、`*.p12`、`id_rsa*` 這類金鑰、`.netrc`、`.npmrc`、
  `.pypirc`、`*.tfvars`、`*.tfstate`、`credentials*`、`secrets.*`、`*secret*.json`、`service-account*.json`，
  以及 `.ssh/`、`.aws/`、`.gnupg/` 底下的所有檔案。腳本只以路徑判斷，自己也不開啟它們。
- 可讀檔案中看起來像機密值的行（私鑰、常見權杖、URL 中的帳密、`password=` 這類寫法），腳本只回報路徑與行號，
  Claude 不在對話、草稿與養分中引用其值，需要時只記錄位置。
- 寫入前腳本再掃描一次草稿，符合機密樣式或依據指向機密檔案時拒絕寫入。
- 限制：樣式比對無法涵蓋所有機密；Claude 讀取可讀檔案時一定會看到其中的內容，只能靠指示不引用。
  請不要把機密值放在一般的程式碼與文件中。

## 不做的事

- 不修改 `.sdd-export/` 以外的任何檔案，也不刪除任何檔案；`.sdd-export/` 要移除時由你自己刪除。
- 不執行建置、測試、套件安裝、格式化或專案自己的腳本；git 只用只讀的指令。
- 不呼叫 Spec Kit（`speckit-*`），不要求導入 Spec Kit。
- 不提交、不 push：養分要不要提交到 repo 由你決定。
- `.sdd-export/` 已有不是本 skill 產生的檔案時，不讀取也不覆蓋，回報後停止。
