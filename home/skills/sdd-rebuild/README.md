# sdd-rebuild

在新專案執行，讀取舊專案的「養分」（`/sdd-export` 的產出），讓你逐項保留、修改、合併、拆分或捨棄原則、功能與教訓，
加入這一代的新需求；你確認最終摘要後，由 Spec Kit 依相依順序產生 constitution 與 spec，並在新專案留下世代紀錄，
供這個專案日後再以 `/sdd-export` 重生時使用。

## 用法

| 指令 | 作用 |
|---|---|
| `/sdd-rebuild <舊專案路徑>` | 在新專案以舊專案的養分重建；沒有給路徑時 Claude 會問你，不會自行搜尋 |

- 舊專案要先執行過 `/sdd-export`。還沒有養分時，本 skill 可以照 sdd-export 的規則代為匯出：匯出前後都會請你確認，
  而且只在舊專案寫入 `.sdd-export/`；你也可以選擇自己到舊專案執行 `/sdd-export` 再回來。
- 只能由維護者輸入 `/sdd-rebuild` 啟動（`disable-model-invocation: true`），Claude 不會主動使用。
- 一個專案只重建一次：新專案已有 `.sdd-rebuild/lineage.json` 時會停止。要加需求用 `/sdd-grill`；要再生下一代，
  在這個專案執行 `/sdd-export` 後另開新專案。

## 前置需求

- 新專案已導入 Spec Kit（沒有時請先執行 `/sdd-init`）。
- 同時部署 `sdd-export` 與 `sdd-grill`：本 skill 載入它們的腳本（養分與世代紀錄的讀取與驗證、Spec Kit 的狀態與驗證），
  匯出時照 `sdd-export` 的 SKILL.md、追問新需求時照 `sdd-grill` 的「Rules for questioning」。缺少時所有指令都會停止。
- `uv`：腳本 `scripts/sdd_rebuild.py` 一律以 `uv run` 執行，只用 Python 標準函式庫。

## 流程

1. **讀養分**：腳本的 `check` 檢查新專案的 Spec Kit、舊專案的路徑、養分與舊專案的世代紀錄。Claude 只使用腳本輸出的養分，
   不讀舊專案的任何檔案（plan、tasks 與程式碼都不會帶進新專案）。舊專案的世代紀錄無法使用時，會說明影響並請你選擇
   停止處理（建議）或只以養分繼續。
2. **新專案已有的內容**：已有 constitution 時預設保留、經你同意才修訂；已有 spec 時可以把養分的功能對應到既有 spec
   （不產生新的、不修改既有的）。
3. **逐項決定**：先問全部原樣保留或逐項檢視；逐項時依原則、功能（含需求）、教訓的順序一次一項並附建議。
   標為待確認（`pending`）的項目一定一題一項請你決定，不會當成事實寫入。
4. **新需求**：照 sdd-grill 的追問規則釐清到有結論才加入，排入相依順序；技術選型留給 plan。
5. **教訓**：依教訓提出的調整一項一題、標示來源教訓，未經你同意不改變原則或需求；不再適用的教訓可以捨棄。
6. **確認**：腳本的 `preview` 組出世代紀錄並檢查（每個來源項目都有去處、新的 `id` 沒有用過、待確認項目都已決定，
   以及 sdd-export 自己的規則），Claude 呈現保留、修改、合併、拆分、捨棄、新增的項目、採用的教訓與 spec 的順序，請你確認。
7. **constitution**：經 `speckit-constitution` 產生，只放確認過的原則，產生後雙向比對。
8. **逐份 spec**：依順序一次一份經 `speckit-specify` 產生（不指定編號），每份產生後以 `claim` 記下它的資料夾，再與摘要比對。
9. **世代紀錄**：`verify` 確認既有文件未被改動、編號符合相依順序後，`lineage` 寫入 `.sdd-rebuild/lineage.json`。
10. **收尾**：`.specify/feature.json` 指向第一份產生的 spec，清除進度，回報每份 spec 的位置與順序；下一步由你在主 session
    輸入 `/sdd-drive`。本 skill 不開始 plan 或實作。

確認最終摘要之前，constitution、spec 與世代紀錄都不會被寫入；唯一的寫入是進度。

## 進度

- 位置：新專案的 `.specify/sdd-rebuild/`（`progress.json` 與一份固定內容的 `.gitignore`），不入庫。
- 每個決定後保存；中斷後再執行 `/sdd-rebuild` 會從腳本算出的下一步接續（逐項決定途中、constitution 產生後、
  spec 產生後尚未記錄、世代紀錄寫入前等），不會重複產生已存在的 spec。
- 快照：第一次保存時記下養分與舊世代紀錄的完整內容。舊專案之後改變或消失都不影響接續；確認前若養分改變，
  會列出差異並問你要不要改用新的養分，確認後一律以快照為準。
- 成功完成後清除。中途要重新開始時，已產生的 constitution 與 spec 會保留，下一次重建把它們當成既有內容；
  世代紀錄寫入後不能重新開始。

## 世代紀錄

- 位置：新專案的 `.sdd-rebuild/lineage.json`（另有讓它在各平台都維持 LF 的 `.gitattributes`）。它 MUST 提交到 repo：
  這個專案下一次 `/sdd-export` 需要它，不入庫的話換一台機器匯出就會變成第一代。是否提交由你決定，本 skill 不會提交。
- 內容由腳本依 sdd-export 定義的格式組成（世代編號、每個項目首次出現與被修改的世代、來源、被捨棄的項目），
  寫入前以 sdd-export 的程式驗證，並模擬下一次匯出。
- `derived_from` 補入祖先：腳本以養分與舊專案的世代紀錄建立「`id` → `derived_from`」的祖先表；保留與修改的項目沿用
  並補入祖先，合併與拆分的項目以被合併或被拆分的 `id` 為直接來源再補入祖先（直接來源在前、深度優先展開、去重）。
  經過「合併再拆分」的項目因此仍記得最早的來源，那些 `id` 不會在之後被重用。
- 確認後才加入的內容（比對 constitution 時你同意保留的多出規則、產生 spec 時澄清得來的內容）不在世代紀錄中，
  下一次 `/sdd-export` 時會被當成那一代新增的項目；結束報告會列出它們。

## 已知限制

維護者接受的取捨：

- 同一代內第二次匯出合併了第一次匯出才建立的項目時，第一次匯出記下的來源只在被取代的養分裡，世代紀錄中也沒有，
  會遺失（匯出時的合併或拆分只能記下直接來源，平常由下一次重建從舊專案的世代紀錄補上祖先）。
- 被捨棄項目的來源只保留到捨棄為止（捨棄紀錄沒有 `derived_from`）；被捨棄的項目本身仍在 `discarded`，不能重用，
  但只靠它才看得到的更早的 `id` 之後可能被重用。
- 舊專案的世代紀錄無法使用（被刪除、格式較新、不符合規則、世代不符、不是 sdd-rebuild 寫的）而你選擇略過時，
  只存在其中的祖先會遺失。這個選擇會在最終摘要與結束報告中列出。

## 不做的事

- 不修改舊專案（你確認的匯出除外，且只寫 `.sdd-export/`），也不在舊專案執行改變 `.git/` 的指令。
- 不讀舊專案的 plan、tasks 與程式碼，不把它們帶進新專案。
- 不覆蓋既有的 constitution 與 spec，不手寫 Spec Kit 的文件。
- 不開始 plan、tasks 或實作，不提交、不 push。
