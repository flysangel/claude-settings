# Data Model: sdd-update 更新 Spec Kit

所有路徑都相對於專案根目錄，一律以 `/` 分隔，兩個平台相同。專案根目錄的定義與 003 相同：
目前目錄位於 git 工作目錄內時是它的最上層，否則是目前目錄。

本功能沿用 [003 的 data-model.md](../003-sdd-init/data-model.md) 的導入紀錄與內容識別資訊，這裡只寫差異與新增的部分。

## 導入紀錄（Record）

位置與格式不變：`.specify/sdd-init.json`，`schema` 為 1。由 sdd-init 建立，本功能讀取並改寫。

### 對 003 格式的變更

| 欄位 | 003 | 004 之後 |
|---|---|---|
| `entries[].origin` | `"speckit"` \| `"sdd-init"` | 多一個值 `"sdd-update"`：本功能建立的比對副本 |
| `entries[].sha256` | 建立時的內容雜湊 | 意義統一為「`speckit_version` 這一版在這個路徑提供的內容」的雜湊；對未被修改的檔案兩者相同 |
| `speckit_version` | 導入的版本 | 導入或最近一次更新完成的版本 |
| `status` | 上一次導入是否完整結束 | 上一次導入**或更新**是否完整結束 |

新增的規則：

- `origin` 為 `sdd-update` 的項目，`path` MUST 位於 `.specify/sdd-update/` 之下且以 `.new` 結尾，
  `staged_executable` MUST 為 false；其他 `origin` 的項目 MUST NOT 位於 `.specify/sdd-update/` 之下。不符合的紀錄視為無效。
- sdd-init 判斷「已完整導入」時，不要求 `origin` 為 `sdd-update` 的檔案存在。
- 其餘規則（不含絕對路徑與個人資訊、路徑範圍、UTF-8 與 LF、鍵值順序固定）不變。

### 各種項目在更新後的 `sha256`

| 項目 | 更新後的 `sha256` | 之後如何被判定 |
|---|---|---|
| 被取代、新建立，或原本就與新版相同的 Spec Kit 檔案 | 新版內容的雜湊 | 未修改 |
| 被保留的 Spec Kit 檔案（在紀錄內） | 新版內容的雜湊 | 被修改，直到維護者把它合併成與新版完全相同 |
| `.specify/memory/` 下的項目 | 不變 | 與更新前相同 |
| `.specify/.gitattributes`（`origin: sdd-init`） | 不變 | 與更新前相同 |
| 比對副本（`origin: sdd-update`） | 副本內容的雜湊，等於對應檔案的新版雜湊 | 移除時內容未變才刪除 |

不在紀錄內的檔案（導入前就存在的 Spec Kit 檔案）更新後仍然不在紀錄內。

## 版本

| 名稱 | 來源 | 用途 |
|---|---|---|
| 紀錄的版本 `R` | 紀錄的 `speckit_version`，一定是穩定版（`N(.N)*`） | 回報的「原版本」；判斷是否需要更新 |
| 官方設定的版本 `P` | 專案 `.specify/init-options.json` 的 `speckit_version`；檔案不存在、無法解析或不是字串時視為沒有 | 只用來判斷專案是否比最新穩定版還新 |
| 最新穩定版 `L` | 以 003 的方法向 PyPI 查詢 | 更新的目標 |

比較規則：取版本字串開頭的數字段（`1.5.0rc1` 取 `(1, 5, 0)`），逐段以整數比較，長度不足的補 0。

| 條件（依序判斷） | 結果 |
|---|---|
| `R` 或 `P` 的數字段大於 `L` | 比最新穩定版還新：不更動 |
| `R == L` 且 `status` 為 `complete` | 已是最新穩定版：不更動 |
| `R == L` 且 `status` 為 `applying` | 被中斷的導入：停止，請維護者先執行 `/sdd-init` |
| 其他（`R < L`） | 更新到 `L` |

## 受保護的路徑

`.specify/memory/` 之下的所有路徑（constitution 與它的範本資訊）。本功能對這些路徑不建立、不取代、不刪除、
不寫比對副本、不輸出任何一行，紀錄內的項目原樣保留。

`specs/` 與專案的其他內容不需要列為受保護：本功能寫入與刪除的路徑只會是下列三類，其餘一律不讀不寫。

| 類別 | 範圍 |
|---|---|
| Spec Kit 檔案 | 新版官方產出的路徑，以及紀錄內 `origin` 為 `speckit` 的路徑；MUST 位於 `.specify/` 或 `.claude/skills/speckit-*/` 之下 |
| 本專案工具自己的檔案 | `.specify/sdd-init.json`、`.specify/.gitattributes`（不存在時才建立） |
| 比對副本 | `.specify/sdd-update/` 之下 |

## 比對副本

被保留、且新版仍提供的檔案 `<P>` 的新版內容。

| 性質 | 內容 |
|---|---|
| 路徑 | `.specify/sdd-update/<P>.new`，`<P>` 是專案相對路徑的全部（包含開頭的 `.`） |
| 內容 | 新版官方產出的位元組，原樣寫入 |
| 模式 | 一般檔案，不設定執行權限，不加入暫存區 |
| 紀錄 | 每份一筆，`origin: sdd-update`；所在的新目錄列入 `created_dirs` |
| 生命週期 | 每次實際更新開始時，紀錄內全部的比對副本先被刪除（不論內容是否被改過，它們是本功能自己的檔案），再寫入這一次的 |

對應關係是雙向固定的：由比對副本的路徑去掉前綴 `.specify/sdd-update/` 與後綴 `.new` 就得到 `<P>`。

「仍待合併」的定義（已是最新穩定版時用來決定要不要列出）：比對副本存在、`<P>` 存在，
且兩者的雜湊（換行正規化後）不同。比對副本不存在、`<P>` 不存在，或兩者相同，都不列出。

要寫入比對副本的路徑上已有檔案、而它不在紀錄內時，是衝突：規劃階段就停止，不寫入任何內容。

## 暫存產出（Staging）

與 003 相同：官方工具以新版在專案之外的暫存空目錄產生的檔案樹，只存在於一次執行期間，結束時（包含失敗）刪除。
產出的路徑 MUST 通過 003 的路徑檢查，且 MUST NOT 是紀錄本身或位於 `.specify/sdd-update/` 之下；否則視為官方工具執行失敗。

## 更新的動作

規劃階段的輸出，只存在於記憶體。對「暫存產出」與「紀錄內 `origin` 為 `speckit` 的項目」的聯集中、
不受保護的每一個路徑各判定一次。`cur`、`rec`、`new` 分別是專案檔案目前的雜湊、紀錄內的雜湊、新版內容的雜湊。

| 動作 | 新版提供 | 專案內 | 紀錄內 | 條件 | 檔案的處理 | 紀錄的處理 |
|---|---|---|---|---|---|---|
| `create` | 是 | 不存在 | 不論 | | 建立 | 列入或更新，`sha256 = new` |
| `same` | 是 | 存在 | 不論 | `cur == new` | 不寫入 | 原本在紀錄內的更新為 `new`；不在的維持不在 |
| `update` | 是 | 存在 | 是 | `cur == rec` | 以新版取代 | `sha256 = new` |
| `keep` | 是 | 存在 | 是 | `cur != rec` | 不動；寫比對副本 | `sha256 = new`；比對副本另列一筆 |
| `keep` | 是 | 存在 | 否 | | 不動；寫比對副本 | 檔案不列入；比對副本列一筆 |
| `remove` | 否 | 存在 | 是 | `cur == rec` | 刪除 | 移除 |
| `keep-orphan` | 否 | 存在 | 是 | `cur != rec` | 不動；沒有比對副本 | 移除 |
| `forget` | 否 | 不存在 | 是 | | 無 | 移除 |

- 判定依表中由上而下的順序，`cur == new` 優先於 `cur == rec`。
- 專案內的路徑存在但不是一般檔案（目錄或符號連結）時，視為 `cur` 與任何雜湊都不同。
- `create` 與 `update` 的檔案把工作目錄的模式設成與暫存產出相同。
- `create` 且副檔名是 `.sh` 的檔案，以及 003 定義的「待補登的 `.sh`」，在專案是 git repository 時執行
  `git add --chmod=+x` 並把 `staged_executable` 設為 true；失敗時的處理與 003 相同（stderr 一行 `note:`，維持 false）。
- `update` 的檔案不加入暫存區，index 內既有的項目不改寫。
- `remove` 的檔案若 `staged_executable` 為 true、仍在 index 且不在 `HEAD`，以 `git rm --cached` 取消。
- `remove` 之後，由深到淺刪除 `created_dirs` 中已經變空的目錄，並把它們從 `created_dirs` 移除。
- `.specify/.gitattributes`：不存在時建立並列入紀錄（`origin: sdd-init`），視為一個 `create`；已存在就不動。

## 狀態轉移

```text
status=complete，R < L
  ──規劃（只讀）──▶ 寫入紀錄：status=applying、版本仍是 R、entries = 原有項目 ∪ 要新建的檔案 ∪ 新的比對副本
  ──刪除舊的比對副本 → 寫入新的比對副本 → 建立 → 取代 → 刪除 → 加入暫存區──▶
  寫入紀錄：status=complete、版本 = L、entries 為更新後的結果

status=applying，R < L（上一次更新或導入被中斷）
  ──與上面完全相同的流程，重新判定──▶ status=complete、版本 = L

status=complete，R == L ──▶ 只讀取；列出仍待合併的檔案；不寫入
```

取得版本、執行官方工具與規劃都在第一次寫入之前；這些步驟失敗，或規劃時發現衝突，專案內沒有任何異動。

中斷後重新判定為什麼會收斂：

| 中斷前已完成的事 | 再次執行時的判定 |
|---|---|
| 檔案已被取代為新版 | `same`（`cur == new`），紀錄更新為 `new` |
| 檔案還沒被取代 | `update`（`cur == rec`） |
| 新檔案已建立 | 已在 `applying` 的紀錄內，`same` |
| 新檔案還沒建立 | `create` |
| 不再提供的檔案已刪除 | `forget` |
| 被保留的檔案 | 從未被寫入，仍是 `keep`；比對副本在紀錄內，重寫 |

取代檔案時先寫到同目錄的暫存檔（檔名為原檔名加固定後綴）再以 `os.replace` 換上；
再次執行時同一個暫存檔會被覆寫後換上，不會留下寫到一半的檔案。
